03 / FirmwareIntegration responsibility

Application commands + board services

Declares discoverable commands and metadata once with USBSCPI_DEFINE_COMMANDS (or registers scpi_command_t tables); supplies context storage, line and I/O buffers, callbacks, and optional locks. Implements GPIO, ADC, radio features, and any downstream block sink.

Owns USB descriptors, capabilities and remaining USBTMC control callbacks, SDK initialization, pins, tasks, and interrupt setup.

Alternative USB stacks: TinyUSB glue is optional. Another transport can call usbscpi_on_rx() directly and implement cfg.usb_tx. Each active transport needs its own core context, line buffer, I/O buffer, and reply callback. The SPSC ring helper backs application queues and the record data plane.

A USBTMC query completes in four steps

Host writes

*IDN? arrives on bulk-OUT. The adapter passes payload and completion status to the core.

Core dispatches

libscpi runs the command callback. Result bytes flow through the configured usb_tx callback.

Adapter buffers

The adapter accumulates the response and sets MAV (message available). It waits for the host read.

Host reads

The IN request callback transmits the buffered response. Completion releases it, clears MAV, and re-arms OUT.

Integration contracts

Memory & execution ownership

Allocate suitably aligned opaque-context storage using usbscpi_sizeof(), then call usbscpi_init(). The application supplies line and optional I/O buffers. The core embeds fixed parser, command, and error buffers; the vendored libscpi configuration disables dynamic allocation. Each transport has its own core context. The default TinyUSB glue binds one global core context and uses one static response buffer. usbscpi_task() is currently a no-op; receive handling and command callbacks run synchronously in the caller’s context.

Binary I/O & response limits

DATA:WRITE streams into application callbacks. DATA:READ? obtains bytes using data_avail/data_read, then emits a SCPI arbitrary block through usb_tx. DATA:FREE? reports the configured sink capacity. An application may use the ring helper, DMA, or another queue behind these hooks. Those sinks are integration choices. The TinyUSB adapter’s default 4096-byte response buffer is compile-time configurable; large result sets need bounded responses, as in the scan examples.
